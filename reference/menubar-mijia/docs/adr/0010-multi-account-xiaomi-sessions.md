# ADR-0010：多小米账号会话、按账号合并设备与分组展示

日期：2026-11-03　状态：已接受

## 背景

`MiSessionStore` 在唯一的钥匙串槽位 `mi_session` 中保存一个裸 `MiSession`，`MiCloudProvider` 只轮询这一个会话。用户同时拥有国内区和海外区账号时，第二次扫码会覆盖第一次登录；#134 只解决了同一账号下的多个家庭切换。

## 决定

1. **账号列表保存在原槽位**：`mi_session` 的值升级为 `{version:2, accounts:[MiSession]}`。读取时同时接受旧的裸对象，重新编码为 v2 并写回；`passToken` 仍然不落盘（ADR-0004）。账号身份取既有的 `region + userId` 哈希（`MiSession.historyScopeIdentifier`），同账号同区域重扫只更新凭据，不新增账号。
2. **组合式 provider**：新增 `MiAccountsProvider`，为每个 `MiAccount` 创建一个现有 `MiCloudProvider`。每账号保留独立的设备/房间/规格/属性值缓存、轮询循环、退避与会话过期处理；组合层只合并快照并转发调用。这样避免把账号维度塞进不含账号的 `MiotPropKey` 缓存，也不改动已测试的单账号 provider。
3. **合并规则**：`SmartDevice.id` 继续使用原始 `did`，收藏、别名、自定义分组、排序、卡片尺寸与能耗历史不需要迁移。房间与家庭 id 前缀账号 id，避免跨账号同名冲突。`SmartDevice` 与 `HomeOption` 增加 `accountId` / `accountLabel`（掩码 userId）供面板分组。同一 `did` 出现在多个账号（共享家庭）时只展示一次，命令路由到按账号顺序的首个所有者。
4. **调用路由**：命令按 `DeviceCommand.targetEntityId` 中的 `did` 找到所属账号；传感器历史按 `deviceId` 路由；摄像头按 `device.id` 路由，停止流时通知所有所有者。一个账号会话过期只清空该账号的设备，其他账号继续轮询。
5. **展示**：设置页列出全部账号及其区域，可逐个添加或移除；账号数大于 1 时，面板把剩余设备按账号分区，家庭菜单按账号嵌套。单账号与未登录的界面保持不变。
6. **平台范围**：本决定先落地 macOS。Windows 的 `secureStore.ts` 仍保存单个会话，继续单账号运行；采用同一 v2 信封是后续工作。

## 后果

- 用户无需重新扫码即可从单账号升级；新增账号不再覆盖已有账号。
- 请求量随账号数线性增长，每个账号仍按面板可见性节流，并各自处理 429 退避。
- 传感器历史作用域仍绑定首个账号；移除首个账号会切换作用域并暂时看不到旧历史（后续按账号命名空间化）。
- 不支持设备扫描会遍历全部已登录的米家账号及已连接的 Home Assistant 数据源。
- 共享设备只保留一张卡片，卡片归属于首个账号；其他账号对该设备的在线状态与属性值不参与展示。
